# 근거 수집 개선의 검증 범위

이 문서는 로컬 테스트 통과와 실제 서비스 연동 성공을 구분하기 위한 검증 기준이다. 공식 API를 사용하지 않는다. 사용자 계정의 인증 자료를 테스트에 복사하지 않는다.

## 로컬에서 자동 검증할 것

| 검증 대상 | 입력 상황 | 기대 동작 |
| --- | --- | --- |
| 검색 카드 연결 | 첫 카드 요약 없음, 두 번째 카드 요약 있음 | 첫 카드에 두 번째 요약을 붙이지 않음 |
| 출처 필터 | 블로그 결과에 쇼핑·광고·나무위키·위장 도메인 혼입 | 검증된 블로그 근거로 집계하지 않음 |
| 추출 상태 | 200 응답이지만 지원하는 카드 구조 없음 | 정상 근거 수집 성공으로 처리하지 않음 |
| 정상 빈 검색 | 실제 결과 없음 표시 | 접근 차단이나 네트워크 장애와 구분 |
| 오류 | 403, 429, 5xx, timeout, 통신 실패 | 상태와 원인 구분, 성공 자료 캐시 금지 |
| 제한 유지 | 프로세스 종료·재실행, 유예 미만 | 원격 요청 없이 제한 상태 유지 |
| 캐시 만료 | TTL 지난 자료, 손상된 저장 파일 | 만료 자료를 새 근거처럼 제공하지 않음 |
| 독립 소스 | 네이버 검색만 제한 | 자동완성·다른 트렌드 수집은 별도 상태로 검사 |
| 근거 판정 | 검색 제한 + 유효한 사용자 링크 본문 | 원고 유형의 근거 조건을 충족하면 경고와 함께 진행 가능 |
| 근거 판정 | 링크만 있음, 빈 본문, AI 요약만 있음 | 확인된 원문으로 인정하지 않음 |
| 원고 유형 | 최신 이슈의 기사 없음, 후기의 경험 자료 없음 | 필요한 근거가 부족하므로 보류 |
| 렌더 페이지 | 내용이 늦게 나타남, 준비 조건 미충족 | 조건 충족까지 제한 시간 대기, 미충족 시 명시적 실패 |
| 렌더 페이지 | 로드 오류·차단 문구 | 성공 200·빈 성공으로 캐시하지 않음 |
| 경쟁도 | 조회 실패·발행일 부족 | 미측정으로 표시, 실측 점수를 만들지 않음 |

## 실제 서비스에서 따로 확인할 것

로컬 Electron fixture 테스트는 브라우저 엔진에서 추출 로직이 동작하는지 검증한다. 실제 네이버가 같은 마크업을 제공하는지, 계정 로그인과 스마트에디터에 정상 입력되는지는 별도다.

1. 공개 수집 진단을 한 번 실행하고 각 소스의 상태와 대표 결과 URL·제목을 확인한다. 제한이 나타나면 추가 요청을 중단한다.
2. 기관 자료가 중요한 글은 표시된 URL의 원문에 해당 자격·금액·기간이 있는지 확인한다. 요약만 있는 자료는 상세 주장 근거로 사용하지 않는다.
3. 사용자가 앱에서 직접 Claude와 네이버에 로그인한 후, 한 편을 생성해 근거·경고·보류 표시를 확인한다.
4. 원고의 제목·본문·이미지·지도 등 사용한 요소가 에디터에 입력됐는지 확인한다.
5. 임시저장 성공 알림과 저장된 원고 내용을 확인한다. 실제 발행은 별도 사용자 동작이다.
6. 예약 테스트도 우선 한 편으로 제한해 새 프로세스에서 캐시·차단 유예와 strictEvidence가 적용되는지 확인한다.

## 성과 판정

검색 결과 관찰과 순위 측정은 원고 품질의 보조 정보다. 비로그인 PC 결과·측정 시각·검색 범위에 따라 달라진다. 조회 실패를 순위 미노출로 바꾸지 않는다. 한 주제에서 글을 검토·발행한 뒤 기존 1·3·7·14·28일 성과 기록으로 관찰한다. 이번 수집 로직 개선만으로 노출 상승을 주장하지 않는다.

## 중요한 경계

URL이 확인됐다는 뜻과 해당 내용이 사실이라는 뜻은 다르다. 출처 연결 검사는 ‘어느 페이지에서 가져왔는가’를 보존하며, 내용의 진위·최신성·원고 주장과의 일치는 별도 검수한다. 검색 결과 요약이 있는 것만으로 기사 본문을 읽은 것으로 표시하지 않는다.

원고 생성에 사용한 사용자·기관 원문은 최종 사실 대조에도 전달돼야 한다. 생성 단계에서는 유효한 자료라고 인정하고 사실 대조 단계에서는 누락하면, 근거가 있는 주장도 확인 불가로 판정할 수 있다.

키워드 랭킹에 기본 가중치가 필요하더라도 실측값과 구분해야 한다. 실제 gap 조회가 실패했을 때 UI·결과 메타데이터의 경쟁도는 null/미측정이며, 정렬 계산에 쓰는 중립 가중치를 측정된 gap=60으로 표시하지 않는다.

## 현재 기록

개선 전 이 PC에서 오프라인 테스트 37개와 정적 검사가 통과했고, 공개 수집 doctor는 8종을 반환했다. 아래는 2026-10-05 개선 작업 중 부모가 직접 실행한 결과이며, 최종 변경 뒤 갱신한다.

| 명령 | 실행 결과 | 범위 |
| --- | --- | --- |
| npm test | 검토 수정 후 89/89 통과 | 네트워크·실제 모델 호출을 격리한 회귀 검사 |
| npm run check | 최종 통합 후 종료 코드 0 | IPC 60개와 JavaScript 문법 검사. 새 모듈·검증 스크립트는 별도 node --check도 통과 |
| git diff --check | 통과 | 변경 파일의 공백 오류 |
| npm run test:rendered-browser | 부모 최종 재실행 8/8 통과, 종료 코드 0 | 실제 Electron의 지연 자료·카드 출처 연결·시간초과·제한 문구·로드 실패·HTTP 429/500·창 정리 |
| npm run doctor | 종료 코드 0, 뉴스 요약 7·기사 2·제목 8·후기 8·블로그 8·자동완성 10·트렌드 32 | 공개 웹의 응답·건수 확인. 검색 제한 재현 없음 |

위 doctor의 검색 결과 관찰은 진단기의 객체 건수 계산 오류 때문에 EMPTY 0으로 표시됐다. 동일한 저장 캐시를 네트워크 호출을 차단한 수집기로 다시 읽어 measured=true, sections 6개, topDocs 6개와 resultKind=ok를 확인했다. 진단기의 sections와 topDocs 계산을 회귀 테스트로 수정한 뒤, 같은 캐시로 12건·OK 판정을 확인했다. 공개 요청을 반복해서 재검사하지 않는다. 기사 종류별 본문 경로는 live 실행 이후에 추가 수정됐으며, 실제 기사 연동 재검증과 의미상 키워드 관련성 검수는 남아 있다.

독립 검토는 “검색 결과 없음” 문구가 무관한 섹션에 있으면 파서 실패를 정상 빈 결과로 숨기는 결함을 재현했다. 해당 경계와 기사 종류별 본문 출처 일치, 요약의 원문 승격 방지는 회귀 테스트에 포함돼 통과했다. 개별 기사 본문 수집의 일부 기존 catch는 실패를 null로 반환하므로 항목별 HTTP 원인 진단은 아직 제한된다.

실제 Claude 생성, 네이버 인증, 스마트에디터 주입·임시저장과 발행 성공은 검증하지 않았다. 사용자 계정이나 인증 세션을 로컬 테스트로 복사하지 않았다. 이번 구현만으로 검색 노출이나 사실 정확성을 보장하지 않는다.

브라우저 검증의 중간 실패도 조사했다. 명시적인 실행 파일 경로가 Playwright의 Electron 준비 로더를 생략했고, 숨은 제어 창 연결 대기도 실패했다. 프로젝트의 설치된 Electron을 기본 탐색으로 실행하고 로컬 fixture의 메인 프로세스 진입점을 직접 호출하도록 수정했다. 수집 창이 모두 닫혀도 테스트 앱이 기본 종료되지 않도록 유지하며, 시작·종료·프로필 정리에 제한 시간을 뒀다. 부모의 최종 실행은 8개 통과와 정상 종료를 확인했고, 실행 뒤 fixture Electron·테스트 Node 프로세스가 남아 있지 않았다.

초기의 정책 테스트 한 번은 모델 실행을 막는 stub 누락으로 실제 Claude 실행 경로에 진입했다. 응답 없이 종료됐으며 모델 요청 전송 여부는 확정하지 못했다. 작업자는 자신이 실행한 프로세스의 종료를 확인했다. 이후 정책 테스트 및 최종 통합 검증은 stub을 적용했다.
