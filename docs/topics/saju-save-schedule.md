# 사주 원고 입력 후 저장·예약

2026-10-07 기준.

사주 탭에서 바로 생성하거나 보관함의 원고를 에디터에 넣으면 제목과 본문 일부가 실제로 들어갔는지 확인한 뒤 네이버 임시저장을 요청한다. 저장 완료를 확인하지 못하면 성공으로 표시하지 않는다. 사진·썸네일 입력까지 끝난 뒤 저장한다.

글 만들기 아래의 예약 발행 옵션은 기본으로 꺼져 있다. 옵션을 켜면 날짜와 시간을 한국 시간으로 지정한다. 과거 시각과 잘못된 날짜는 생성 전에 거부한다. 네이버 예약 화면의 분 선택은 10분 단위이다.

예약은 기존 OS 스케줄러의 반복 원고 생성과 별개다. 네이버 발행 설정에서 예약을 선택하고 달력을 이동해 날짜를 고른 뒤 시·분을 지정한다. 예약 선택 및 날짜·시간 표시값이 모두 일치하고 임시저장이 확인된 경우에만 최종 등록을 요청한다. 네이버에 등록된 예약은 앱을 종료해도 네이버가 처리한다.

자동 입력·자동 게재는 네이버 이용약관상 제한될 수 있다. 기본 임시저장이 자동 입력의 위험이 없다는 뜻은 아니다. 운영자는 내용을 검토하고 계정 운영 방침을 결정해야 한다.

실제 예약 등록 완료 검증은 공개 또는 예약 게시물을 만들기 때문에 이 개발 검증에서는 수행하지 않는다. 예약 화면의 설정·표시값 확인과 실제 등록 완료 검증은 구분한다.

복원 팝업이 에디터 위에 떠 있으면 준비 완료로 처리하지 않는다. 해당 팝업의 취소 버튼만 찾아 닫힘을 확인하며, 닫지 못하면 전체선택·삭제·제목 입력을 중단한다. 이미 글쓰기 화면에 있는 경우와 늦게 팝업이 뜨는 경우에도 검사한다.

검증: 예약 설정은 2026-10-28 10:30, 2026-11-03 00:50, 2026-11-15 14:20에 대해 화면 표시값 일치를 확인하고 최종 발행 없이 취소했다. 실제 복원 팝업은 새 가드로 한 번 클릭 후 사라진 것을 확인했다. 기본 임시저장 전체 흐름과 실제 예약 등록 완료는 아직 수동 확인이 필요하다.

## 원고마다 새 문서에 넣기 (2026-10-07 추가)

- **진입 검사:** 글 만들기를 누르면 생성(토큰 사용) 전에 "작성 중인 글이 있습니다" 팝업이 떠 있는지만 확인한다. 팝업이 있으면 닫지 않고 멈추며 사용자가 직접 처리해야 한다. 글쓰기 화면이 아니면 글쓰기 화면을 열기만 하고, 열린 뒤 팝업이 있으면 같은 방식으로 멈춘다.
- **새 문서 준비:** 생성·보관함 입력 직전에 (1) 쓰던 내용이 있으면 확인된 임시저장을 먼저 하고 실패하면 중단한다. (2) 내용이 비어 있어도 항상 글쓰기 화면을 다시 열어, iframe 문서에 붙인 표식이 사라진 새 문서인지 확인한다. (3) 복구 팝업은 이때만 가드로 닫는다(방금 저장한 글의 복구 팝업). (4) 새 문서가 비어 있음을 확인하고 새 표식을 붙인다. 어느 단계든 실패하면 기존 내용을 지우지 않고 중단한다.
- **입력 직전 확인:** 새로 준비한 문서는 `clearEditorBody`로 지우지 않고, 표식이 같고 비어 있는지만 확인한 뒤 입력한다.
- **빈 에디터 판정:** 플레이스홀더 노드(`[class*=placeholder]`)를 뺀 글자나 이미지·표 등이 있으면 내용 있음이다. 실제 제목이 정확히 "제목"이어도 플레이스홀더 노드가 아니면 내용으로 보고 저장한다. 빈 에디터는 저장하지 않는다.
- **저장 확인:** 저장 전에 이미 떠 있던 토스트는 무시하고, 새 토스트 또는 저장 개수 증가가 있을 때만 성공으로 본다. 확인 못 하면 실패이다.
- **동시 실행:** 생성과 보관함 넣기는 하나의 잠금을 공유한다.
- **테스트·한계:** 가짜 에디터 시뮬레이터와 최소 가짜 DOM으로 연속 두 원고(첫 저장본 보존), 빈 에디터, 저장·이동 실패, 복구 팝업, 제목만 있는 내용, 오래된 토스트를 검증한다. 플레이스홀더 노드의 실제 클래스 구조와 문서 교체 시 표식 소멸은 라이브 DOM으로 확인하지 않았다. 틀리면 중단(데이터 손실 없음) 쪽으로 동작한다.
