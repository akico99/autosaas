# 여행 상품 URL 가져오기 검증

기준일: 2026-10-08 (KST)

## 구현 범위

`connectImportProduct({url})`은 공개 HTTP(S) 상품 상세 페이지를 가져와 상품 제안을 만든다. 네이버 패키지 페이지에서는 URL의 상품 ID와 일치하는 `#__NEXT_DATA__` Apollo 레코드만 선택하고 공개 본문 DOM의 가격 행과 대조한다. 일반 페이지는 요청 URL과 일치하는 Product/Offer JSON-LD와 명시적인 본문 항목을 사용한다. Product에 명시적 URL이 있으면 그 주소가 요청 URL과 맞아야 한다. URL 없는 Product는 해당 페이지에 Product가 하나뿐일 때만 허용한다. 본문 안의 JSON-LD도 파싱하며, 화면 발췌를 만들 때는 별도 DOM 복제본을 사용해 스크립트를 보존한다. 추천 상품이나 다른 출발 상품의 값은 섞지 않는다.

가져오는 값은 상품명, 제공사, 목적지, 유형·박/일, 포함·불포함, 취소조건, 공개된 출발일·연령별 KRW 요금과 옵션 조건이다. 네이버 패키지 가격은 공개 본문에서 같은 연령 라벨과 같은 금액이 확인되는 경우에만 옵션에 넣는다. 원문 발췌, 상세 URL, source ID와 원래 `collectedAt`을 유지한다. 옵션의 `priceCheckedAt`은 원래 수집 시각을 사용한다.

UI는 자동 수집 사실을 검토 전 제안으로 표시한다. 사용자는 하나 이상의 옵션을 선택하고 원문 확인 체크를 한 뒤 저장한다. 서버 정규화도 출처 원문에 값과 발췌가 들어 있는지 확인하며 일치하지 않는 사실을 `unverified`로 되돌린다. 할인·쿠폰·포인트는 전체 페이지 발췌에서 기본 요금과 따로 확인할 수 있지만, 현재 별도 쿠폰/포인트 필드로 구조화하지 않으며 옵션의 `amountMinor`에도 합치지 않는다.

## 실제 공개 URL 확인

인증 없이 공개 HTML을 수집해 parser와 실제 importer 경로에서 아래 값을 확인했다.

| 공개 URL | 추출된 상품·일정 | 저장 가능한 기본 요금 |
| --- | --- | --- |
| `https://pkgtour.naver.com/products/verygoodtour/APP7579%7CWE35-20261103` | 참좋은여행, 하노이·하롱베이, 2026-11-03, 3박 5일 | 성인 499,000원 · 소아 499,000원 · 유아 100,000원 |
| `https://pkgtour.naver.com/products/ybtour/JCP40960000-20261101` | 노랑풍선, 일본 대마도, 2026-11-01, 1박 2일 | 성인 229,000원 · 소아 229,000원 · 유아 50,000원 |

첫 페이지에 표시된 474,050원 쿠폰가와 23,702P 적립, 두 번째 페이지의 222,130원 쿠폰가와 11,106P 적립은 각각 기본 요금과 다른 값으로 남는다. 두 페이지 모두 목적지·기간·연령별 가격 옵션을 추출했고 `missingFields`가 비어 있었다. 링크 발급 주소는 생성하지 않으며, 신규 수입 상품의 `affiliateUrlRaw`는 빈 문자열이다.

## 저장 경로 검토

- 가져온 출처의 URL, 발췌와 `collectedAt`은 UI payload에서 보존되고, 서비스는 현재 카탈로그의 출처와 새 출처를 ID 기준으로 병합한다. ID 충돌 시 UI helper가 새 ID를 만들고 상품 사실의 `sourceId`도 함께 remap한다.
- 옵션의 `priceCheckedAt`은 importer의 수집 시각을 보존한다. 기존 옵션과 동일 조건이면 옵션 ID를 재사용하고, 선택하지 않은 기존 옵션은 남긴다.
- `buildTravelProductImportPayload`는 같은 상품 URL을 편집하는 경우 기존 제휴 링크를 유지한다. 다른 상세 URL을 기존 상품에 가져오거나 가져온 뒤 폼 상세 URL을 바꾸면 저장을 거부하므로 기존 링크가 다른 상품에 연결되지 않는다. 두 거부 경로는 집중 UI 회귀 테스트로 확인한다.
- 일반적인 신규 URL 가져오기에서는 제휴 링크가 만들어지지 않는다. 상세 URL과 제휴 링크의 용도는 계속 분리된다.

BrandConnect의 로그인 세션 DOM은 부모가 브라우저에서 별도로 확인한 정보다. 앱 URL importer는 그 세션에 연결되지 않으며 세션 DOM을 수집하지 않는다. 이 구현은 공개 페이지 HTML만 읽고 공식 상품 API나 모델을 호출하지 않는다. 앱 전체의 원고 생성은 기존 생성 경로를 계속 사용한다.

## 테스트와 현재 상태

21개 변경 파일을 원래 앱 폴더에 적용하고 해시를 대조했다. 원래 앱 폴더에서 전체 `npm test` 246/246, `npm run check`, `git diff --check`가 통과했고, 최종 Electron 스모크도 URL guard와 수동 흐름을 포함해 종료 코드 0으로 끝났다. Electron 앱 로그인 화면과 프로세스 PID 90648을 확인했다. 수동 보완 저장 시 가져온 수집 시각을 기존 출처 시각보다 우선하는 처리도 집중 테스트와 Electron 화면 검사에서 확인했다. 앞서 실행한 렌더링 브라우저 검사는 8/8이었다. 원격 commit/push는 하지 않았다.

URL import 변경은 `feat/travel-product-import` 격리 worktree와 원래 앱 폴더 양쪽에 반영되어 있다. Collector는 공개 HTML과 서버 렌더링 데이터/JSON-LD에 의존하므로 제품 정보를 브라우저 실행 뒤에만 구성하는 페이지에서는 부분 정보 또는 미확인 필드가 나올 수 있다. URL 자동 등록과 실제 공개 페이지 값은 [프로젝트 상태](../STATUS.md)에도 요약했다.
