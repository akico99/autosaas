# 프로젝트 상태

## 여행커넥트 확장 — 2026-10-08

### 최신 저장소 반영 범위

공개 상품 URL 가져오기, 네이버 발급 링크의 격리된 브라우저 해석, 상품·가격·출처 자동 저장, 키워드 추천과 직접 주제 입력, 생성 전 기존 상품 자동 재확인, 프로필 추가 폼과 작성 상태 안내를 함께 반영한다. 원고 없는 결과의 신규 보관함 저장을 막고 이전 빈 요청은 작성하지 못한 요청으로 표시한다. 임시 화면 검증 스크린샷은 저장소 반영 대상에서 제외한다.

실사용에서 발급 링크 상품 수집과 확인은 완료됐지만 Claude SDK 원고 요청이 구독 세션 한도로 거절됐다. 이 앱은 `runClaude.js`에서 API 키를 제거하고 로그인한 Claude 구독 인증을 사용한다. 한도 오류는 상품 등록 보류와 다른 외부 생성기 제한이다. 실제 모델을 통한 완성 원고 생성은 아직 확인되지 않았으며, 현재 한도 메시지는 원문으로 표시된다. 이번 커밋에 이를 해결한 것으로 기록하지 않는다. 자동 재확인과 생성 연결은 가짜 작성 함수를 사용한 회귀 검사로 검증했다.

### 원고 작성 흐름 정리

실사용 요청 세 건이 작성 전 검사에서 중단됐지만 빈 보류 기록을 원고 보관함에 저장하고 있었다. 해당 상품에는 가격과 링크가 있었으나 예전 수동 등록 경로의 제휴 확인 상태가 `unknown`으로 남아 있었다. 생성 버튼에서도 저장된 발급 링크를 자동 재확인하도록 연결했고 기존에 선택한 옵션을 유지한다. 제외한 상품은 자동으로 재활성화하지 않는다. 가격이 6시간 이상 지났거나 가격 근거가 없으면 같은 경로로 재수집한다. 재확인 실패 시 실제 원인과 다음 행동을 표시하고 작성 모델 호출 전에 멈춘다.

원고가 없는 결과는 새 초안으로 저장하지 않는다. 이전 빈 요청 기록은 삭제하지 않고 작성하지 못한 요청으로 구분한다. '예약 가능 여부를 근거로 확인해야 합니다' 안내는 '발급 링크 확인이 필요합니다'로 변경했다. 실제 예약 가능 여부를 링크 확인 결과로 단정하지 않는다. 실제 저장 자료의 복사본과 발급 링크로 `unknown` → `verified` 복구 및 기존 성인 옵션 ID 보존을 확인했다. 실사용 카탈로그 자체는 검증 과정에서 수정하지 않았다.

상단에서 원하는 키워드를 직접 입력하고 생성할 수 있다. 해외 목적지는 해외 여행으로 자동 선택하며 사용자가 직접 선택한 값은 유지한다. 작성 중·확인 단계 실패·작성 실패·보관함 저장 완료를 구분한다. 기존 빈 요청의 오래된 예약 가능 여부 문구도 자동 확인 안내로 표시한다. 전체 회귀 `npm test` 290/290, 정적 검사와 `git diff --check` 통과. 마지막 문구 보완 후 기존 빈 요청 화면 검사를 다시 통과했다. 실제 작성 모델 호출은 하지 않았다. 현재 실행 중인 앱은 자동 종료하지 않았으며 재실행 후 적용된다.

### 발급 링크 자동 진행 — 현재 작업 폴더

여행 메뉴 상단에서 브랜드커넥트 발급 `naver.me` 링크를 넣고 자동 진행을 시작한다. 격리된 Electron 창이 실제 이동 경로를 관찰한 뒤 공개 상품 페이지를 읽는다. 상품 정보·출처·출발일별 연령 옵션을 저장하고 목적지와 출발지에서 키워드 후보를 준비한다. 사용자가 키워드를 고르면 기존 검색용 생성기에 연결하여 초안을 보관함에 저장한다. 기존 프로필은 재사용하며 처음에는 작성 프로필을 한 번 등록해야 한다.

자동 확인은 서버에서 관찰한 브랜드커넥트 중계 경로와 상품 원문 발췌를 근거로 한다. 발급 링크 확인은 예약 가능 여부를 보증하지 않는다. 확인한 원화 기본 요금만 옵션으로 선택하며, 쿠폰가·포인트는 제외한다. 가격 확인 후 6시간이 지나면 키워드 선택 때 다시 수집한다. 근거가 부족하거나 검색 수집이 제한되면 해당 오류와 생성기의 보류 사유를 표시한다. 사진 사용권 확인과 에디터 전달·발행은 기존 별도 흐름을 유지한다. 공식 API 연동은 추가하지 않았다.

실제 `https://naver.me/GdTuMXPg` → 브랜드커넥트 중계 → 노랑풍선 대마도 상품으로 이동하는 경로를 검증했다. 임시 카탈로그에 상품 1개와 성인·소아 229,000원, 유아 50,000원 옵션을 저장했고 저장 뒤 발급 링크와 가격 근거가 검증 상태를 유지했다. 작성 모델은 호출하지 않았다. 실페이지 검증 도구는 `scripts/validate-auto-import-live.js`이며 Electron으로 실행한다.

설계와 구현 계획은 [자동 진행 설계](superpowers/specs/2026-10-08-issued-link-autopilot-design.md), [구현 계획](superpowers/plans/2026-10-08-issued-link-autopilot-plan.md)을 참고한다. 아래 공개 URL 등록 기록은 이전 단계의 수동 보완 경로에 관한 기록이다.

최종 통합 검사: `npm test` 283/283, `npm run check`, `git diff --check` 통과. Electron 화면 회귀 검사는 자동 등록·키워드 선택·생성 요청·보관함 갱신, 가격 재수집, 키워드 오류 재시도, 생성 중 중복 실행 차단을 가짜 생성 함수로 확인했다. 실페이지 상품 저장은 별도 실제 발급 링크로 확인했다. 실제 작성 모델의 원고 품질·네이버 발행은 이번 검사 범위에 포함되지 않는다. 변경한 원본 앱 폴더에서 Electron을 다시 실행했다. commit/push는 하지 않았다.

### 공개 상품 URL 자동 등록

격리된 `feat/travel-product-import` worktree에 공개 상품 URL 가져오기를 구현했다. URL 가져오기는 공개 HTML과 페이지의 서버 렌더링 자료를 읽어 상품명·제공사·목적지·여행 기간·포함/불포함·취소조건, 출발일별 연령 옵션 가격, 원문 발췌와 수집 시각을 제안한다. 사용자가 옵션을 선택하고 원문을 확인해야 저장된다. 자동 수집은 사실 검토나 제휴 대상 확인으로 취급하지 않는다.

두 공개 네이버 패키지 상품 URL을 실제 수집해 확인했다.

| 상품 | 출발일·일정 | 공개 기본 연령별 요금 |
| --- | --- | --- |
| [참좋은여행 하노이·하롱베이](https://pkgtour.naver.com/products/verygoodtour/APP7579%7CWE35-20261103) | 2026-11-03, 3박 5일 | 성인 499,000원 · 소아 499,000원 · 유아 100,000원 |
| [노랑풍선 대마도](https://pkgtour.naver.com/products/ybtour/JCP40960000-20261101) | 2026-11-01, 1박 2일 | 성인 229,000원 · 소아 229,000원 · 유아 50,000원 |

상품 옵션의 가격은 공개 상품 페이지의 연령별 기본 요금이다. 쿠폰 적용가와 적립 포인트는 페이지 원문 발췌에서 구분해 확인할 수 있지만 옵션 판매가로 저장하지 않는다. 예를 들어 첫 페이지의 쿠폰가 474,050원과 23,702P, 두 번째 페이지의 쿠폰가 222,130원과 11,106P는 각각 기본 옵션 가격과 분리된다.

수집한 `collectedAt`은 출처에 그대로 보존되고 각 옵션의 `priceCheckedAt`에도 사용된다. UI에서 출처를 확인하고 옵션을 선택한 뒤 확인해야 저장한다. 저장 시 서버도 출처 발췌·값·시각을 검사하며 근거가 맞지 않는 사실은 미검토 상태로 남긴다. 새 상품의 제휴 링크는 비어 있다. 링크 발급과 BrandConnect 연동은 이 구현에 포함되지 않는다. 로그인된 BrandConnect 페이지의 DOM은 부모가 별도로 확인한 자료일 뿐, 앱은 세션 DOM을 읽거나 가져오지 않는다. 이 URL 가져오기 경로는 공식 API와 모델을 호출하지 않는다.

통합 검토에서 확인한 URL 불일치 위험은 저장 단계에서 차단한다. 다른 상세 URL을 기존 상품에 합치거나 가져온 뒤 폼의 상세 URL을 바꾸면 저장을 거부하므로 이전 `affiliateUrlRaw`가 다른 상품에 연결되지 않는다. 같은 상품 URL을 수정하는 경우 기존 제휴 링크는 보존된다. 구현 21개 파일을 원래 앱 폴더에 복사했고 파일 해시를 대조했다. 원래 앱 폴더에서 `npm test` 246/246, `npm run check`, `git diff --check`, URL guard와 수동 흐름을 포함한 최종 Electron 스모크(종료 코드 0)가 통과했다. 원래 앱 창의 로그인 화면과 PID 90648도 확인됐다. 수동 보완 저장 시 가져온 수집 시각을 기존 출처 시각보다 우선하는 처리도 집중 테스트와 Electron 화면 검사에서 확인했다. 원격 commit/push는 하지 않았다. 검증 상세는 [여행 상품 URL 가져오기 검증](topics/travel-product-import-validation.md)을 참고한다.

여행커넥트의 첫 노출 목표는 네이버 검색이다. 상품에 맞는 키워드와 예약 전 질문을 바탕으로 정보형·비교형 블로그 원고를 작성한다. 홈판, Threads·X, 쇼핑 전용 탭은 후속 범위다. 여행·쇼핑은 명시적인 서비스 종류와 서로 다른 고지문을 사용한다.

기존 검색 생성기·원고 보관함·프로필·성과 기능을 재사용한다. 사용자가 공식 도구에서 발급한 제휴 링크와 상품 상세 주소를 따로 등록하고, 출처 발췌와 확인한 상품 조건을 관리한다. 원문 링크, 가격과 옵션, 고지, 근거와 확인 시점은 생성·수정·에디터 전달 때 검사한다. 검색 수집 차단은 낮은 경쟁도로 표시하지 않는다.

여행 기획·작성은 기존 SDK의 Opus, 필수 답변과 1차 사실 대조는 기존 Haiku를 사용한다. 파일 파싱·매칭·시간·링크 검사는 코드가 처리한다. 개발도 설계·생성 연결과 독립 검토에 고성능 모델을 사용하고, 반복 구현·회귀 검증은 별도 작업자에게 맡겼다. 실제 모델 호출 없이 합성 상품과 출처로 검증했다.

격리 작업 공간에서 상품·출처 등록, 옵션 비교, 키워드 선정, 사진 사용권 확인, 원고 생성·가져오기·수정·보관함, 기존 성과 기록과 수동 에디터 전달을 구현하고 원본 앱 작업 폴더에 적용했다. 에디터 전달의 재검사 오류를 수정하고 실제 `app.html` 전달 훅과 에디터 어댑터를 실행하는 회귀 검사로 성공·보류·원고 동시 수정·링크 변경·잠금과 이전 설정 복원을 확인했다. 모델·이미지 처리와 네이버 에디터는 가짜 함수로 대체한 오프라인 검증이다.

최종 독립 검토를 통과했다. 2026-10-08 부모가 원본 작업 폴더에서 다시 `npm test` 222/222, `npm run check`, `npm run test:rendered-browser` 8/8, `node scripts/tests/connect-ui-electron.js`, `git diff --check`의 통과를 확인했다. Electron 화면 검사는 긴 상품명, 다중 옵션 비교·두 번째 옵션의 가격 재확인, 한국 시간 입력, 키워드 실패·출처 표시, 생성 실패 후 버튼 복구, 보관 원고 수정과 보류·검수 전달을 확인했다. 실제 발급 상품·상품 사진 사용 권한, Claude 실생성, 인증된 네이버 에디터의 카드·임시저장 동작은 이 검증에 포함되지 않는다. 자세한 범위는 [여행커넥트 명세](topics/travel-connect-tab-spec.md), [구현 계획](superpowers/plans/2026-10-07-travel-connect-tab-plan.md), [결정 기록](topics/travel-connect-decisions.md)을 참고한다.

오른쪽 여행 메뉴의 스크롤 누락을 수정했다. 동적 마운트 컨테이너가 내용 높이만큼 늘어나 내부 스크롤이 생기지 않는 문제였으며, 레이아웃에서 컨테이너를 투명하게 처리해 여행 패널이 기존 flex 영역에 맞도록 했다. 화면 검사에 실제 앱 CSS와 상단 바·분할 영역·오른쪽 패널 구조를 사용한다. 수정 전 780px 창에서 여행 패널 높이가 2,626px로 늘어나는 실패를 재현했고, 수정 후 1120×780과 900×640 창에서 휠 스크롤, 고정 탭 메뉴, 아래쪽 성과 버튼 접근과 기존 화면 검사를 통과했다. 이 수정 후에도 `npm test` 222개와 정적 검사를 다시 통과했다.

## 완료된 것

키워드 조사 보고서는 검색광고 XLSX와 네이버 자동완성 후보를 병합한다. 앱 화면과 CLI를 제공하며, XLSX 처리를 위해 exceljs 의존성을 추가했다.

검색용 원고 기준 v1은 searchBrief.js에서 검색 의도 8종을 분류하고 의도별 필수 답변과 분량을 적용한다. searchContentCheck.js는 생성 뒤 필수 답변을 검사하고 1인칭 경험 표현을 탐지한다. 결과는 발행 준비, 검수 필요, 발행 보류로 나누며 문제점이 적은 후보를 채택한다. 근거 없는 노출 단정과 분량 부풀리기 규칙을 제거했고, 예약 실행은 보류 원고를 저장하지 않는다. 생성 품질은 search-quality.jsonl에 기록한다.

naverSearchGuard.js는 검색 요청을 직렬 처리하고 최소 1.5초 간격과 30분 캐시를 적용한다. 차단 감지 시 30분, 반복 차단 시 2시간 동안 요청을 중단한다. 403·429 종류와 유예, 압축 캐시 및 원래 수집 시각은 search-state.json에 저장한다. AI 브리핑은 로그인 세션과 분리된 persist:naver-search 세션에서 렌더링하며, 탐색용 요약으로 취급한다.

serpObserve.js는 검색 결과 섹션을 관찰한다. 의도가 불명확한 키워드는 관찰 결과를 사용해 보정하고, 관찰 결과를 생성 프롬프트에 반영한다.

성과 추적은 tracker.js, perf:* IPC, 검색용 탭 패널로 구성한다. 생성 글을 자동 기록하고, 발행 글은 제목 매칭이나 수동 주소로 연결한다. 1·3·7·14·28일에 순위를 확인하며 한 번에 최대 6개를 처리하고 사용자가 버튼을 눌렀을 때만 실행한다. 의도·상태별 요약을 제공하고 search-performance.json에 저장한다.

## 주제 탭 1단계 — 사주보는 수달

사주 주제 설정, 우선순위 키워드, 블로그 프로필 저장, 키워드 재사용 경고, 서비스 근거를 포함한 검색용·홈판용 생성 맥락, 원고 검수 상태, CTA 링크, 사이트 캡처와 직접 추가 사진 자산, 블로그별 이미지 프레임, 주제별 생성 기록 패널을 추가했다. 기존 홈판용·검색용 생성 화면과 예약 경로는 구버전 그룹에서 계속 사용한다. 기본 화면은 사주보는 수달이며 무주스키샵은 비활성 자리로 표시한다.

서비스 사실 근거는 현재 검색 근거 검증기 인터페이스와 맞춰 `sourceType: user-source`로 전달한다. 명세의 `user-provided` 이름은 기존 인터페이스에서 인식되지 않아 사용하지 않았다. 사주 사이트 캡처는 별도 세션에서 2배 확대와 스크롤바 숨김을 적용하고 페이지당 최대 3장을 저장한다. 2단계 통합검색 파서는 광고·플레이스·관련문서·브랜드 콘텐츠·제목 블록과 사이트·발행 글 적중 위치를 추출한다. 사주 탭과 구버전 성과 패널은 렌더 통합검색 결과를 사용하며, 주제 분석 갱신은 10개 키워드를 15~25초 간격으로 관찰하고 차단 시 중단해 일자별 JSON으로 저장한다. 테스트는 합성 HTML·가짜 수집 함수로만 했다. 실제 앱 화면, sajuotter.com 캡처, Naver 에디터 이미지·OG 링크 삽입과 실서비스 통합검색 파싱은 아직 확인하지 않았다. 상세 결정은 [주제 탭 명세](topics/saju-tab-spec.md)를 참고한다.

## 검증 상태

개선 전 이 PC에서 오프라인 37개와 정적 검사가 통과했다. 개선 후 부모가 npm test를 실행해 89/89 통과를 확인했고 npm run check, 새 수집기·브라우저 검증 스크립트의 node --check, git diff --check도 통과했다. 독립 Luna/max 리뷰에서 확인한 파서 빈 결과 판정 결함은 회귀 테스트로 수정했다.

개선 중 단 한 번 실행한 공개 doctor는 종료 코드 0, 뉴스 요약 7·기사 2·제목 8·후기 8·블로그 8·자동완성 10·트렌드 32건이었다. 이 실행 뒤 기사 종류별 본문 경로를 추가 수정했으므로 최신 코드의 실서비스 기사 동작까지 검증했다고 해석하면 안 된다. 진단기의 SERP 객체 건수 오류는 수정했고 동일한 저장 자료를 네트워크 없이 다시 읽어 6개 섹션과 6개 관찰 제목, 총 12건의 OK 상태를 확인했다.

Playwright의 로컬 Electron 검증은 부모가 최종 재실행해 8/8 통과와 종료 코드 0을 확인했다. 지연 렌더, 카드 출처 연결, 시간초과, 제한 문구, 로드 실패, HTTP 429/500과 창 정리를 검사했다. 테스트 시작·종료의 중간 결함도 수정했다.

실제 Claude 생성, 네이버 에디터 주입·임시저장과 인증된 앱 화면의 동작은 아직 검증하지 않았다. 초기에 모델 호출을 막는 테스트 연결이 누락돼 테스트가 실제 호출 경로로 넘어간 적이 있다. 해당 실행은 중단됐고 응답은 없었으며, 실제 모델 요청 전송 여부는 확인하지 못했다. 이후 회귀 테스트는 모델 실행을 stub으로 격리했다.

2026-10-06 주제 탭 2단계와 캡처·원고 검사 수정 후 `npm test` 110/110, `npm run check`, `git diff --check`가 통과했다. 통합검색 파싱·속도 제어는 합성 HTML과 주입된 수집 함수로 검증했으며, 이 실행에서는 Electron 앱이나 네이버에 접속하지 않았다.

## 알려진 문제와 위험

- 작성자 PC에서는 2026-10-04 밤부터 네이버 검색이 일시 제한되어 403과 "검색 서비스 이용이 제한되었습니다"가 반환됐다고 기록돼 있다. 현재 사용자 PC에서 차단됐다는 뜻은 아니다. 과거 원인 조건(IP·요청량·세션)은 당시 진단 로그 없이 확정할 수 없다. 차단이 실제 확인된 환경에서는 요청을 중단하고 사용자가 브라우저의 보안 절차를 직접 진행해야 한다.
- 의도 분류는 키워드 패턴 규칙이므로 애매한 키워드는 일반 정보로 분류될 수 있다.
- 필수 답변 검사와 사실 대조는 저렴한 모델의 판정이므로 오판할 수 있고, 생성당 모델 호출이 늘어난다.
- 통합검색 추적은 별도 로그아웃 `persist:naver-search` 세션의 PC 결과 기준이므로 개인화된 결과와 다를 수 있다.
- 블로그 단위 평가(C-Rank)는 원고만으로 해결할 수 없다. 한 블로그에서 주제를 섞어 발행하면 불리할 수 있으며 이는 운영 문제다.
- 자동화 대량 발행은 네이버 정책상 위험하므로 예약 생성량을 늘리지 않는다.
- 이미지 수집 단계는 변경되지 않았으며 여전히 5장을 채우려 한다.
- competition.js의 조회 실패·날짜 부족은 measured=false와 gap=null로 표시한다. 키워드 정렬의 내부 중립 가중치는 실측 경쟁도로 노출하지 않는다. 순위를 보장하는 지표는 아니다.
- 공개 웹 마크업과 페이지 본문 관련성을 완전히 검증할 수는 없다. 출처 연결 검증과 실제 주장에 대한 사실 검수는 별개다. 여러 프로세스가 동시에 실행될 때 전역 요청 큐를 공유하는 기능은 구현하지 않았다.

## 다음 할 일

1. 제한이 실제 나타난 환경에서는 유예를 지키고 사용자가 브라우저 보안 절차를 직접 완료한다. 현재 PC가 차단됐다고 가정하지 않는다.
2. 소스 변경 뒤 로컬 회귀 검증을 먼저 실행하고, 공개 수집은 제한 상태를 존중하며 최소 횟수로 확인한다.
3. 앱에서 한 편을 실제 생성해 근거·경고·보류 표시, 제목·본문·이미지 주입과 임시저장을 확인한다.
4. 한 주제의 키워드 10~20개를 발행한 뒤 성과 패널로 1·3·7·14일 결과를 기록한다.
5. 결과를 바탕으로 의도별 기준을 조정한다.
6. 이후 후보는 이미지 장수 기준 조정과 크리에이터 어드바이저 유입 검색어 연결이다. 경쟁도 기본값 문제는 이번 구현에 포함됐다.
