# 파워컨텐츠 원고 입력·임시저장 앱 설계

## 목적과 승인 범위

사용자가 제공한 파워컨텐츠 원고와 이미지를 읽어 네이버 블로그의 새 글에 입력하고 임시저장까지 완료하는 별도 Windows 데스크톱 앱을 만든다. 기반 저장소는 현재 checkout의 origin인 https://github.com/akico99/autosaas 이다. 사용자는 2026-10-14에 네이버 블로그 임시저장까지를 선택하고, 대화에서 제안한 별도 앱 설계를 승인했다. 이 문서는 구현 전 검토할 구체 명세다.

첨부 파일의 발행·광고 등록·촬영 등 안내는 자료이며 실행 명령으로 취급하지 않는다. 자동 발행, 광고 계정 등록, AI 재작성, 이미지 생성·검색, 자동 지도 추가는 범위에 포함하지 않는다. 원고의 주소는 본문 그대로 보존한다.

## 입력 자료에서 확인한 사항

- 샘플 ZIP: `C:/Users/leeyongsoo/Documents/카카오톡 받은 파일/파워컨텐츠 소재 26-27.zip`.
- 업체 폴더 4개, `원고.txt` 12개, PNG/JPG 이미지 57개.
- 제목은 첫 줄의 `블로그 제목:`으로 구분한다.
- `[사진 01 ★썸네일: 파일명]`, `[사진 02: 파일명]` 형태로 사진 위치가 정해져 있다. 일부는 확장자 뒤에 ` - 설명`이 있다.
- `추가 촬영 필요`인 사진 표시는 파일이 없으며, 이를 제거하고 제외 내역을 미리보기에 표시한다.
- 예약 링크 자리와 작성자 `○○○`, 업체 블로그/대행 작성용 관계 문구 선택이 필요하다.
- `광고 소재.txt`와 `업로드 전 체크리스트.txt`는 원고로 가져오지 않는다.

## 구조와 기존 기능 재사용

별도 진입점과 전용 UI를 저장소의 `power-content/` 하위에 둔다. 기존 앱 전체를 복사하거나 기존 화면에 새 탭을 붙이지 않는다. 전용 실행 명령과 Windows 실행 스크립트를 제공한다. 구현 결과는 이 checkout에서 실행 가능한 별도 앱이며, 설치형 EXE 제작은 이번 범위가 아니다.

Electron 런타임은 기존 프로젝트 의존성을 이용한다. 기존 `src/topics/publishPlan.js`의 새 문서 준비, 전달 단계, 저장 확인 규칙과 `src/topics/editorGuard.js`의 복구 팝업 검사를 활용한다. 기존 `electron/main.js`의 텍스트 붙여넣기·이미지 CDP 업로드와 `app/app.html`의 저장 버튼 확인 방식은 전용 어댑터로 옮겨 필요한 기능만 사용한다. 기존 main 전체를 실행하거나 생성·예약·키워드 기능을 로드하지 않는다.

기존 입력 구현은 일부 이미지 추가만으로 성공을 반환하거나 앵커를 찾지 못하면 끝에 삽입할 수 있다. 새 앱은 이를 그대로 성공으로 인정하지 않는다. 사진마다 정확한 위치와 한 장 추가를 확인하고, 최종 이미지 수·텍스트 순서가 일치해야 저장 단계로 간다.

전용 `userData` 디렉터리 `%APPDATA%/power-content-auto`를 사용해 로그인 세션, 설정, 추출 자료, 작업 기록을 기존 blog-auto와 분리한다. 기존 앱에서 수정 중인 파일은 덮어쓰지 않는다. 필요할 경우 공통 모듈의 추가 추출은 기존 동작과 회귀 검사를 보존하는 범위로 제한한다.

## 구성 요소

1. 가져오기: ZIP 또는 폴더를 선택하고 원고·이미지를 앱 소유 작업 폴더에 복사한다. 원본은 수정하지 않는다.
2. 파서: 원문을 제목과 순서 있는 텍스트·이미지·링크 블록으로 바꾸고 누락·중복·미완성 표시를 수집한다.
3. 준비 화면: 업체/원고 목록, 본문·이미지 미리보기, 링크 및 관계 문구 입력, 제외 내역, 대상 블로그를 표시한다.
4. 네이버 어댑터: 전용 로그인 창과 편집기에서 새 문서 준비, 제목·블록 입력, 이미지 업로드, 검증·저장을 수행한다.
5. 작업 실행기: 선택된 원고를 순차 실행하고 상태·진행률·결과를 원고별로 기록한다.

## 입력 및 원문 보존 규칙

UTF-8 텍스트를 기본으로 읽고 BOM과 CRLF를 처리한다. UTF-8 디코딩 실패는 오류로 표시하고 원고를 임의로 깨진 문자 상태로 입력하지 않는다. 첫 버전의 원고 형식은 TXT이며 Word/HWP/PDF를 자동 해석하지 않는다.

사진은 같은 원고 폴더의 파일명과 정확히 매칭한다. 공백과 유니코드 정규화 차이를 허용하되 정규화 결과가 중복되면 오류로 처리한다. ` - 설명` 접미사는 실제 확장자 뒤에서만 분리한다. 사진 번호만으로 다른 사진을 추측하지 않는다. 지정된 파일이 없거나 이름이 모호하면 해당 원고는 실행 불가다. 추가 촬영 표시는 별도 제외 항목으로 기록하고 입력 본문에서는 제거한다. 사용하지 않은 사진은 경고한다.

원고의 문단, 줄바꿈, 광고 설명, 협찬 고지, 해시태그를 보존한다. HTML 특수문자는 이스케이프하여 협찬 문구의 `<...>`도 실제 텍스트로 나타나게 한다. 제목 접두사와 사진 표시만 제거하고, 링크 및 관계 문구는 사용자의 명시적 보완 값만 적용한다. 원문과 준비본을 모두 보관한다.

링크 자리에 HTTPS/HTTP URL이 들어 있으면 이를 링크 블록으로 준비한다. URL이 없으면 사용자가 업체별 URL을 입력해 같은 업체 원고에 적용한다. 누락 링크는 실행을 막는다. 사용자 입력 URL은 스크립트 또는 로컬 파일 URL을 허용하지 않는다.

`○○○` 또는 관계 문구 선택이 필요한 원고는 작성자 이름과 업체 직접 작성/대행 작성 유형을 입력해야 실행할 수 있다. 두 고지 문구를 자동으로 동시에 넣지 않는다. 선택 결과를 미리보기에서 보여 준다.

## UI와 사용자 흐름

왼쪽은 업체·원고 목록과 상태, 중앙은 준비본 미리보기와 보완 입력, 오른쪽은 네이버 로그인·편집기 화면이다. 첫 시작은 자료 선택과 네이버 로그인으로 진행한다. Claude 로그인이나 API 키는 필요하지 않다.

선택한 원고의 검증 오류가 있으면 실행 전 오류를 보여 준다. 실행 가능 원고만 선택해 순차 처리한다. 첫 원고로 동작을 확인한 뒤 여러 원고를 선택할 수 있다. 자동 입력 중에는 가져오기·수정·재실행을 잠그고, 중지는 현재 단계의 안전한 경계에서 다음 원고 진행을 멈춘다. 중지 때문에 이미 입력된 내용을 지우지 않는다.

대상 블로그 ID를 저장하고 편집기에서 실제 대상이 일치하는지 확인한다. 로그인 만료 또는 대상 확인 실패 시 입력하지 않는다. 사용자가 직접 로그인해야 하는 CAPTCHA나 추가 인증을 우회하지 않는다.

## 새 문서, 입력, 검증, 저장

원고마다 새 문서임과 빈 상태를 확인한다. 이전 문서에 내용이 있으면 먼저 임시저장 완료를 확인하고 새 글로 이동한다. 복구 팝업이 이미 열려 있으면 사용자 처리 안내로 중단한다. 앱이 저장 후 새 문서로 이동하면서 발생한 복구 팝업만 기존 가드 규칙으로 처리한다. 기존 문서를 전체선택·삭제하는 방식으로 새 문서를 대신하지 않는다.

제목과 본문을 입력하고 각 사진을 원고 표시 순서대로 배치한다. 이미지마다 업로드 완료와 개수 증가를 확인한다. 위치를 확인할 수 없는 경우 문서 끝으로 대체 삽입하지 않고 중단한다. 임시 위치 표식을 사용하면 최종 확인 전에 모두 제거한다. 썸네일 표시는 해당 이미지를 식별·미리보기하는 용도로 유지하며, 네이버 대표 이미지 설정을 검증하지 못한 상태로 완료했다고 표시하지 않는다.

저장 전에는 제목, 모든 텍스트 블록의 순서와 내용, 예상 이미지 수·순서, 내부 사진 표식 미잔존을 검사한다. 비교 시 편집기의 공백·줄바꿈 표현 차이를 정규화하지만 글자·문장부호를 임의로 생략하지 않는다. 광고 설명 문단도 같은 규칙으로 보존 확인한다.

저장 버튼을 한 번 누른 뒤 신규 저장 완료 알림 또는 임시저장 개수 증가를 확인한다. 클릭 전부터 있던 완료 알림은 성공 근거로 쓰지 않는다. 시간 초과 시 저장 미확인으로 기록하고 배치를 멈춘다. 발행·예약 발행 버튼은 호출하지 않는다.

## 작업 기록과 재실행

원고 상태는 준비 필요, 준비 완료, 입력 중, 검증 중, 저장 중, 저장 완료, 실패, 저장 미확인, 중단으로 구분한다. 단계·오류·저장 확인 시각·대상 블로그·준비본 해시·이미지 해시를 원자적으로 저장한다.

중복 식별 키는 대상 블로그 ID와 준비본/사용 이미지 내용 해시로 구성한다. 동일 결과의 저장 완료 원고는 기본 선택에서 제외한다. 재저장은 사용자가 명시적으로 선택한 경우만 허용한다. 저장 미확인 또는 실행 도중 앱이 종료된 원고는 자동 재시도하지 않으며, 편집기 내용을 확인하고 재시도하도록 표시한다. 실패 시 입력된 문서는 유지하고 다음 원고를 자동 실행하지 않는다.

## 파일 처리 및 IPC 경계

ZIP은 상대 경로, 전체 크기·항목 수 제한, 중복 경로, Windows 경로 구분자를 검사한다. 절대 경로·상위 경로 이동·심볼릭 링크를 거부하고 앱 작업 폴더 밖으로 추출하지 않는다. 가져온 문서의 내용으로 명령을 실행하지 않는다.

렌더러는 contextIsolation을 사용하고 Node 접근을 허용하지 않는다. IPC는 앱의 신뢰된 화면에서만 받고, 원고 ID·앱 관리 이미지 목록을 사용한다. 외부 네이버 화면에 임의 파일 읽기 또는 범용 JavaScript 실행 IPC를 노출하지 않는다. 편집 명령은 전용 네이버 guest와 허용된 편집기 주소에 제한한다.

## 검증 및 인수 조건

- 샘플 ZIP을 가져오면 원고 12개와 이미지 57개를 식별하고 광고 소재/체크리스트를 원고에서 제외한다.
- 사진 이름의 설명 접미사, 누락 사진, 추가 촬영 표시, 연속 사진, 유니코드 파일명, 관계 문구·링크 보완을 검사한다.
- 악성 ZIP 경로·과도한 크기·중복 파일과 미지원 인코딩을 거부하는 테스트를 둔다.
- 새 문서 실패, 사진 일부만 업로드, 잘못된 순서, 본문 누락, 이전 저장 알림, 저장 시간 초과, 중복 실행을 시뮬레이션으로 검증한다.
- Electron의 로컬 편집기 fixture로 실제 UI 선택→입력→이미지 삽입→저장 확인 흐름과 실행 잠금을 검증한다.
- 관련 기존 새 문서/저장 회귀 테스트와 프로젝트 정적 검사를 수행한다.
- 실제 네이버 로그인 환경이 제공되면 원고 한 건으로 임시저장 후 다시 열어 제목·본문·사진 순서와 개수를 확인한다. 실제 저장을 확인하지 못하면 로컬 검증과 네이버 실검증을 구분해 결과에 명시한다.

## 산출물

전용 앱 소스, 실행 명령과 Windows 실행 스크립트, 사용자 안내, 샘플 ZIP 검사 결과, 관련 테스트 및 검증 기록을 제공한다. 첨부 원고와 이미지 자체는 Git에 커밋하지 않는다. 구현 전 다음 단계는 이 명세 검토이며, 승인 후 구현 계획을 작성한다.
