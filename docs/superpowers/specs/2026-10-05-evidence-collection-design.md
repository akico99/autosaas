# 근거 수집 안정성과 정확성 개선 명세

## 목표와 확정 조건

사용자는 근거 수집 실패와 STATUS.md의 문제에 대해 자세한 기술 설명 및 실제 구현을 요청했고, 구현 모델을 GPT-6 Luna / max로 지정했다. 공식 API는 사용 불허다. 기존 Electron 앱과 공개 웹 수집을 유지한다. 이번 작업은 수집 결과의 의미와 정확성, 재시작에도 유지되는 제한 처리, 실제 브라우저 검증을 개선한다.

현재 다운로드 기준은 main의 0a68e233ce0673dac8be7d45692278ffd63b8669다. 이번 PC의 doctor는 8종 정상 응답이므로 과거의 403 장애가 현재 재현된다고 가정하지 않는다. 응답 건수와 근거 품질은 별개다. 앱은 자동 발행하지 않고 임시저장까지 처리한다.

## 현재 기술 문제

1. markup.js는 전체 페이지 제목·요약 배열을 위치로 연결한다. 다른 검색 섹션이나 요약 누락이 있으면 출처와 주장 연결이 틀릴 수 있다. doctor에서 블로그 자료에 쇼핑몰·나무위키 제목이 관찰됐다. 검색 URL의 탭 지정만 신뢰하면 안 된다.
2. trends.js 등의 catch→[]와 health 기록이 HTTP 상태·예외 유형을 지운다. 실제 0건, 접근 제한, 시간초과, HTTP 실패, 파싱 실패를 구분해야 한다.
3. guard의 캐시와 차단 유예가 메모리에만 있어 매번 새 예약 프로세스에서 초기화된다. HTTP 429·5xx·렌더 로드 오류를 일관되게 처리하지 못한다.
4. doctor는 search.naver.com 제한 시 독립적인 자동완성·외부 트렌드도 BLOCKED로 표시한다.
5. searchBrief는 검색 제한을 무조건 보류 사유로 삼지만, 사용자 원문이나 검증된 기관 페이지가 충분할 수 있다. 반대로 검색 요약만 있어도 공식 근거로 인정하는 판정이 느슨하다.
6. scrapeRendered는 고정 sleep 후 추출하고 로드 오류를 객체로 반환한다. 호출부가 이를 성공 200으로 포장할 수 있어 실패 결과를 캐시하거나 불충분한 본문을 성공으로 취급한다.
7. competition.js는 실패 시 gap=60, 날짜 부족 시 82를 반환한다. 미측정을 경쟁도 실측으로 오해할 수 있다.
8. 기존 tests와 check는 실제 브라우저 준비·추출 실패를 검증하지 않는다.

## 이번에 구현할 범위

### 1. 결과와 오류의 의미

차단, 제한(429), 시간초과, 네트워크 오류, HTTP 오류, 파싱 실패, 정상 0건을 구분한다. health snapshot/report와 doctor가 원인을 보존하고 표시한다. 기존 public 함수의 반환 형태는 가능한 유지하되 새 메타데이터를 병행 제공한다. 비밀값·쿠키·인증 헤더·본문 전문을 로그에 남기지 않는다.

### 2. 출처와 카드별 연결

검색 결과는 카드 단위로 제목·요약·실제 URL을 함께 읽는다. URL이 확인되지 않는 텍스트를 확인된 근거로 승격하지 않는다. 뉴스와 블로그의 허용 출처 유형을 분리하고 광고·쇼핑·네비게이션 혼입을 차단한다. 내용 전달에 기존 string[]이 필요하면 검증한 구조에서 호환 텍스트를 생성한다. 소스 메타데이터에는 URL, 제목, 출처 종류, 수집 시각, 본문/요약 구분을 제공한다. 게시일은 실제 값이 있을 때만 저장한다. URL·클래스 변경에 취약한 정규식 전면 재작성보다 검증 가능한 카드 파싱을 선택한다.

### 3. 제한 처리와 캐시

기존 직렬 요청 간격과 차단 시 중단을 유지한다. Electron userData 아래 별도 파일에 한도가 있는 공개 자료 캐시와 제한 유예 상태를 저장한다. CLI에도 일관된 저장 위치를 적용하고 테스트는 임시 디렉터리로 격리한다. TTL·크기 제한·잘못된 파일 무시·원자적 저장을 갖춘다. 접근 제한 결과는 성공 자료로 캐시하지 않는다. 오래된 근거를 새 자료처럼 제공하지 않는다. 호스트/소스 단위로 중단 범위를 구분한다. 제한 시 렌더 브라우저로 재시도하거나 우회하지 않는다.

### 4. 근거 충족 여부로 보류

검색 차단 자체는 수집 상태다. 기사/기관 원문, 사용자 제공 링크 본문, 후기 경험 자료 등 원고 유형에 필요한 근거가 충분하면 경고와 함께 진행할 수 있다. 링크 주소만 있고 본문이 없으면 원문 근거로 인정하지 않는다. 최신 이슈 근거 없음·경험 없는 후기는 계속 보류한다. AI 브리핑/검색 요약은 출처 탐색용이며 기관 원문과 동일하게 취급하지 않는다. 자동 예약의 strictEvidence 경로는 생성 전에 부족한 근거를 감지해 모델 호출을 낭비하지 않는다. 근거 충분하다는 판정이 글의 사실 정확성을 보장한다고 표시하지 않는다.

### 5. Electron 렌더 수집과 검증

실패를 명시하고 성공 내용 준비를 확인하는 제한 시간 대기를 구현한다. 기존 Electron을 그대로 사용하며 독립 브라우저를 런타임 수집기로 추가하지 않는다. 최소한 근거 수집용 렌더 경로에 readiness와 응답 상태 검증을 적용한다. 정상 HTTP로 받았지만 파싱 구조가 없거나 JS 렌더가 필요한 경우의 브라우저 사용은 별도 주입 인터페이스로 명확하게 제한한다. 실제 403/429 때는 브라우저 fallback을 실행하지 않는다.

Playwright는 개발 의존성/검증 도구로만 도입한다. 지연 렌더링, 잘못된 카드 연결, 로드 실패, 차단 페이지 등 자체 로컬 fixture 기반 Electron 테스트를 실행한다. 사용자 프로필과 인증 세션은 접근하지 않는다. 실제 Claude 생성·네이버 임시저장 성공은 인증 없이는 검증했다고 주장하지 않는다.

### 6. 작은 측정 오류 수정

경쟁도 조회 실패·날짜 부족은 measured=false와 reason 및 null 점수로 반환한다. 사용처를 점검해 null이 0점·좋은 기회로 자동 변환되지 않도록 한다. 현재 미사용 경로라 하더라도 API 계약과 테스트를 문서화한다.

## 이번 구현에서 제외한 후속 운영/제품 변경

- 이미지 5장 기준 완화: 수집 신뢰성 검증 후 글 유형별 이미지 정책으로 다룬다. 이번에 무관한 이미지 주입 로직을 바꾸지 않는다.
- 검색 의도 자동 분류 정교화: 지금은 모호성 경고와 검수 유지. 추가 모델 호출은 도입하지 않는다.
- 순위 정확도: 기존 측정 범위의 한계를 유지하며 수집 장애를 순위 미노출로 오해하지 않게 한다. 개인화 순위 보장은 하지 않는다.
- 대량 예약 확대·어드바이저 연동·자동 발행은 도입하지 않는다.

## 완료 기준

카드 요약 누락과 다른 섹션 혼입이 근거 연결 오류로 이어지지 않는다. 원인별 진단이 보존된다. 프로세스 재시작 테스트에서도 차단/TTL이 적용된다. 독립 소스는 네이버 검색 차단 중에도 검사된다. 차단+유효 원문은 진행 가능하며 차단+근거 부족은 보류된다. 렌더 실패는 성공으로 캐시되지 않는다. 전체 오프라인 테스트와 정적 검사가 통과하고 Playwright fixture 결과를 기록한다. 공식 API 도입이 없어야 한다.

## 진행 방식

사용자의 이번 요청을 설계 정리와 구현 진행의 명시적 승인으로 적용한다. 추가 단계별 승인 요청 없이 실행한다. 깨끗한 전용 clone에 fix/evidence-collection-reliability 브랜치를 만들었다. 후속 요청인 ‘커밋 푸시’에 따라 이 브랜치의 변경을 커밋하고 원격 저장소에 push한다. 배포, 실제 발행, 로그인 정보 이동은 수행하지 않는다. 코드 구현은 Luna / max 에이전트가 맡고 부모는 문서 및 검토를 담당한다.
